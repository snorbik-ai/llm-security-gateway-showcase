# Public vs private scope

This showcase follows the same pattern used for [Solena](https://github.com/ta-dev-ai) and other professional open-core projects.

## What is public (this repository)

| Content | Included |
|---------|----------|
| Product vision and problem statement | Yes |
| High-level architecture | Yes |
| Demo GIF and screenshots | Yes |
| Tech stack and roadmap | Yes |
| MVP status (honest) | Yes |
| Validation results summary | Yes |
| Author and contact links | Yes |

## What stays private

| Content | Reason |
|---------|--------|
| Full source code (core modules) | IP protection |
| Internal prompts and governance | Security |
| SCB / industrialisation specs | Internal methodology |
| Production configs and secrets | Security |
| Complete forensic notebooks | IP + complexity |
| Internal audit memory and datasets | Size + sensitivity |

## Why not make everything public?

1. **IP** — months of architecture and forensic design work.
2. **Clarity** — recruiters need a clean 10-second signal, not 3 GB of stage archives.
3. **Credibility** — a polished showcase + honest status beats a messy full dump.

## Why not keep everything private?

Recruiters clicking from LinkedIn need to see **AI security work**, not only student React projects.

This showcase closes that gap without exposing the core.
